# Прецеденты: Список дел (To-Do List)

Актёры:
- Пользователь – человек, который ведёт свой список дел.
- Таймер/Система – не человек: по расписанию проверяет сроки дел и напоминает о просроченных.

Связи между прецедентами:
- «Добавить дело», «Отметить дело выполненным» и «Удалить дело» всегда используют «Сохранить данные» (<<include>>): после каждого изменения список записывается в файл.
- «Отметить дело выполненным» можно подключить к «Просмотреть список дел» (<<extend>>): отметку можно сделать прямо из списка.

## Прецедент «Добавить дело»
- Цель: зафиксировать новое дело в списке.
- Основной сценарий: пользователь выбирает пункт меню 1, вводит название и срок; дело появляется в списке и сохраняется.
- Альтернативный сценарий: название пустое – программа выводит сообщение об ошибке и повторяет ввод.

## Прецедент «Просмотреть список дел»
- Цель: увидеть все дела и их статусы.
- Основной сценарий: пользователь выбирает пункт меню 2; программа выводит дела: название, срок и статус («выполнено» или «не выполнено»).
- Альтернативный сценарий: список пуст – программа сообщает, что дел пока нет.

## Прецедент «Отметить дело выполненным»
- Цель: пометить дело как сделанное.
- Основной сценарий: пользователь выбирает пункт меню 3 (или делает это из списка), указывает название дела; статус меняется на «выполнено», данные сохраняются.
- Альтернативный сценарий: дела с таким названием нет – программа выводит сообщение и повторяет ввод.

## Прецедент «Удалить дело»
- Цель: убрать ненужное дело из списка.
- Основной сценарий: пользователь выбирает пункт меню 4 и вводит название; дело удаляется, список сохраняется.
- Альтернативный сценарий: дела с таким названием нет – программа выводит сообщение, список не меняется.

## Прецедент «Сохранить данные» (служебный)
- Цель: сохранить список дел, чтобы он не пропал при закрытии программы.
- Основной сценарий: после каждого добавления, отметки или удаления программа записывает список в файл tasks.txt.
- Альтернативный сценарий: файл недоступен для записи – программа выводит сообщение об ошибке, данные остаются в памяти до выхода.

## Прецедент «Напомнить о просроченных делах» (актёр: Таймер/Система)
- Цель: не дать пользователю забыть о делах, срок которых истёк.
- Основной сценарий: система сравнивает срок каждого невыполненного дела с текущей датой и выводит напоминание о просроченных.
- Альтернативный сценарий: просроченных дел нет – напоминание не выводится.
